# Firmware decisions and deviations — 2026-11-20

Firmware has changed no external contract GPIOs, rails, channels, outline or mounts. Applied lead release notes 1 then 2; they require wiring documentation updates only. No target sources or binary changed.

- Board-domain deviation (read-only, not a firmware contract edit): the contract assigns the same `PWM_*` nets to J_PCA and J_Sx while requiring no signal back-power. Board DEVIATIONS.md item 1 inserts U1 SN74LVC244A, naming J_PCA nets `PWM_*_RAW`. Firmware reconciliation now measures all seven matching U1 paths and OE/supply nets rather than falsely requiring direct copper. Board item 3 also changes J_CTRL/J_PCA from sealed 1×12 positions to actual 2×6 and moves connector rows. WIRING.md reflects measured pad positions/directions; lead/case must still resolve the geometry deviation. Evidence: native PCB SHA256 `32c6e9ddaff8cda39247f041256be938245a10eed1f25d6ff7fb60e6135eb7cb`, engineering/DEVIATIONS.md, engineering/pinout.md and firmware/reports/integration.json. No firmware GPIO change or motion rebuild is needed.
- Release note 2 supersedes the unknown battery/power-bank assumption: 140 g parallel 18650 cells, 1S reference only; model, cell count, capacity, protection and qualified current remain unknown. Wiring points to board POWER_SYSTEM.md for the selected protected/charge/boost chain and explicitly keeps the unqualified pack disconnected. HC-SR04P order evidence does not establish received pinout or Echo level. Fan is always powered from protected LOAD_5V, outside MOTOR STOP/ACT_EN control, with no new GPIO.

- Contract: “chỉ quét trong vùng đã được case kiểm tra” and approximate ±70° is an untested target, not a sealed limit. V0 ships CASE_YAW_MIN=CASE_YAW_MAX=0 because this worktree has no checked case limits. Stationary sweep code exists and is tested with a mock ±30° fixture; actual sweep remains disabled. Integration must import hash-bound case limits as described in INTEGRATION.md, rebuild and check. No physical angle is claimed.
- Contract: conservative autonomous exploration and stop when travel lacks protected sonar coverage. V0 AUTO advances only straight, at a 25% calibrated pulse-span target, for at most 9 seconds, and cuts servo power on blocked, stale or unknown forward data. It does not attempt an unguarded obstacle turn. Manual/CUE pivot commands require fresh front and rear data; side-swipe coverage remains a bench limitation, not a navigation guarantee.
- Contract: preserve actual reference protocol meaning and publish new capabilities. Reference host hard-codes a different MCU MAC, GPIO20/21 and cues-v3 receipt. New identity is tank-v1, GPIO20 stays USB, a new host adapter requires the real target MAC and separately authorized verified receipt. Existing visual/status protocol remains. New ARM and 200ms heartbeat requirements intentionally prevent an old host from moving the new robot.
- Internal engineering targets, untested: 50Hz nominal, 50ms power ramp wait, 300ms turret settle, 350mm clearance, two valid consecutive echoes, 250ms echo freshness, 60ms between any sonar pings, 25ms echo timeout, 750ms control-link lease, 100ms control-loop deadman, 5ms timer polling, 2s task watchdog. Source of PCA frequency/enable settings and LILYGO pin/rotation settings: SOURCES.md. Bench must verify servo neutral, oscillator/pulse calibration, stopping distance and reset-state voltages.

## Release note 8 retarget (2026-11-27)
- Contract text: LILYGO T-Display-S3 pins (GPIO18/17/10/11/12/13/1/2/14) and parallel LCD. Change: target ESP32 DevKit (30-pin ASSUMED), `esp32:esp32:esp32`, SPI ST7789 240×240, new V0 pins in tank/pins.h (SDA21 SCL22 OE26 ACT27 TRIG25/33 ECHO34/35 STOP32; LCD SCK18 MOSI23 CS16 DC17 RST4 BL13). Evidence: build passes (412 KB flash, 31 KB static RAM) and host suites pass; no hardware tested. Cross-team impact: the board published no DevKit table in this worktree; its PCB still carries the old LILYGO connector rows. Board must adopt or replace these pins; `reconcile.py` compares once engineering/pinout.md has an 'ESP32 DevKit' table. Sonar Echo 34/35 are input-only (no pull-ups) and need the board's level shifter driving them. Local STOP moved to GPIO32; DevKit BOOT (GPIO0) still also stops.
- Framebuffer: full 115 KB neither fits static DRAM nor a single heap block on a no-PSRAM ESP32 (tester finding). Now a static 57.6 KB half buffer; Canvas has a row window (y0,h) and each frame renders twice (top, bottom) then streams in 20-row bands. Static RAM 88.7 KB; no large allocation. pet_test checks the halves equal the full render. GPIO16/17 (LCD CS/DC) are PSRAM pins on WROVER DevKits: a WROOM module is assumed. Echo 34/35 float if unplugged; level shifter must drive them.
- Case: printed robot-tank v1 case mounting and any turret yaw limits are not imported; turret stays center-only (CASE_YAW 0/0). No cadsmith WiFi/joystick firmware added (not requested).
- Integration repair (2026-11-27): firmware's provisional pins collided with the board's published map (would have set ACT_EN high at boot). Adopted board map: OE25 ACT26 TRIG_F32 TRIG_R33 STOP27 (SDA21 SCL22 ECHO34/35 and display pins already matched). reconcile.py now compares against engineering/esp32-pinmap.json and accepts J_CTRL.12=STOP_N (contract NC; note 8 lets the board assign local stop). Earlier "provisional pins" wording in this file is superseded. Case yaw limits: case/firmware-limits.json still absent; turret stays center-only until the case publishes it, then import into tank/mechanical_limits.h and rebuild.
- Case limits imported (2026-11-27): case/firmware-limits.json (passed, yaw -70..+70, hashes verified by reconcile.py) -> mechanical_limits.h; this supersedes the earlier center-only deviation. core_test invalid-turret examples changed to ±71. WIRING.md leftover LILYGO GPIO10/13/2/12/1 text corrected to DevKit pins.
